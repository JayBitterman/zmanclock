I want to build a new feature or project. Interview me to understand the requirements:

1. Ask me what I want to build (if I haven't already said)
2. Ask about:
   - Target users and core use case
   - Technical stack preferences or constraints
   - Must-have vs nice-to-have features
   - Any existing code or APIs this integrates with
   - Edge cases I might not have considered
   - Data model / storage needs
   - Auth / permissions requirements (if applicable)
3. Keep asking follow-up questions until we've covered the hard parts
4. Don't ask obvious questions — dig into the tricky stuff

Once we've covered everything, write a complete spec to SPEC.md with:
- Overview
- Requirements (numbered, testable)
- Technical approach
- Data model (if applicable)
- API endpoints (if applicable)
- UI wireframe descriptions (if applicable)
- Open questions (if any remain)

Then tell me to start a fresh session to implement from the spec.
